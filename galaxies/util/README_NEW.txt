Классификация источников SRGe в поле радиоисточника BSA внутри области 
локализации S190425z 
---------------------
Папки названы по имени источников SRGe. Внутри каждой 
папки лежит JSON файл в котором указана классификация источника и флаг, 
указывающий, что все компаньоны внутри области локализации данного SRGe 
выбиваются за 90% доверительный интервал на расстояние до источника GW. 
Также, там находится таблица с кандидатами в компаньон в SRGe источник.

Статистика
----------
1. Количество источников SRGe = 318
2. Количество заматченных источников SRGe = 233 (73%)
3. Количество вероятных QSO = 95
4. Количество вероятных галактик = 126
5. Количество вероятных звезд = 12
6. Количество SRGe, которые не попадают по расстоянию = 129

Методика идентификации
----------------------
1. Внутри 2-сигмовой области локализации возможного радио-компаньона в S190425z 
с центром в RA=16h 27m +/- 90 arcmin, Dec=13d 15m +/- 30 arcmin выбраны 
источники из следующих каталогов: SDSS-DR16, DESI-DR8, GLADE+, NED-LVS, CatWISE,
GAIA-DR3, а затем кросс-матчены между собой. В качестве опорного каталога взят 
SDSS-DR16. Кросс-матчинг выполнен по методу ближайшего соседа с ограничением по 
угловому расстоянию в sep = 3.0 arcsec. В результате составлена так называемая 
"мастер-таблица". При этом каталоги SDSS-DR16 и DESI-DR8 были отфильтрованы по
флагам качества (не брались самы плохие флаги), а к SDSS-DR16 была дополнительно 
применена операция по удалению дубликатов. Для этого выбирались группы источников 
попадающие в кружок 3.0 arcsec, а затем, чтобы не усреднять их параметры, 
выбирались параметры источника с наилучшими флагами качества.


2. Затем мастер таблица была преобразована следующим образом:
	а) Координаты во всех строчках усреднены ra_fin_j = sum(ra_i) / count(ra_i)
	   dec_fin_j = sum(dec_i) / count(dec_i), где индекс i отвечает за номер 
	   столбца, а j за номер строки. При этом учитывалось, что могут координаты 
	   в одном из столбцов отсутствовать и при усреднении такие столбцы не 
	   использованы.

	b) Всем источникам присвоенно расстояние и его ошибка 
	   D_L_fin +/- e_D_L_fin по следующему порядку:
	    i) по спектроскопии из NED-LVS
	    ii) по спектроскопии из SDSS-DR16
       iii) по фотометрии из SDSS-DR16
	    iv) по фотометрии из DESI-DR8
	    v) по фотометрии из NED-LVS
       vi) по GAIA-DR3
	    vii) по методу, который указан как неизвестный из NED-LVS

   c) Всем источникам присвоен флаг high_PM, если такой источник имеет значимое
      proper motion, S/N > 4 по GAIA-DR3.

   c) Классификация оптических источников произведена так:
       i) Сначала по NED-LVS (G, QSO, GPair, RadioS)
       ii) Далее по SDSS-DR16 (class < 5 -- галактика G, иначе звезда S)
       iii) Затем по CatWISE (W1-W2 > 0.8 -- квазар QSO)
       iv) По DESI-DR8 (pstar < 0.5 -- G, иначе звезда S)
       v) Далее по GAIA-DR3
       vi) Если расстояние до объекта определенно и оно в пределах ~27 кпк 
           (размер галактики), то такой источник обозначен как звезда.

    d) Источникам присвоен флаг beyond_dist_uplimit, если с учетом ошибки их
       расстояние не попадает в доверительный интервал 90%.
3. С помощью обработанной мастер-таблицы (PMT) произведен кросс-матчинг 
   источников SRGe с помощью метода ближайшего соседа. Ограничение по угловому 
   расстоянию выбрано следующим образом: sep = pos_r98c_i, где pos_r98c_i -- 
   радиус локализации i-го источника SRGe. В результате, 233 из 318 
   источников SRGe имеют кандидаты в оптический компаньон (70%). 
4. На следующем шаге источники SRGe классифицированы по следующему алгоритму:
   a) Если среди кандидатов преобладает один из классов, скажем QSO, тогда 
      данному источнику SRGe присваивается данный класс
   b) Иначе, когда количество источников = количеству классов и нельзя какой-то
      доминирующий класс выделить, класс выбирался так:
      i) Если среди классов есть QSO, то SRGe выделен как квазар
      ii) Если есть G, но нет QSO, то SRGe выделен как галактика
      iii) Если нет G, QSO, но есть S, то данный SRGe -- звезда
      iv) В остальных случаях, если нет QSO,G,S, то класс определяется как
          "class_1,class_2,class_3", например, "GPair,RadioS"
